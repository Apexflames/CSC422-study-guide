TOPIC 1

Memory Systems

What computer memory is, the primary/secondary/cache/register classification, and the RAM & ROM family.

1.1 What is computer memory?

Computer memory is any physical component that can temporarily or permanently store data, information, or instructions.

🗣️ Plain English

Memory is just "where the computer keeps things" — whether that's for a split second while it's calculating something, or permanently, like a saved file.

Memory is classified into four types:

  • Primary memory — RAM and ROM
  • Secondary memory — hard drives, flash drives
  • Cache memory — fast memory near the CPU
  • Register memory — the fastest memory, inside the CPU itself

1.2 Primary Memory — RAM

RAM (Random Access Memory) is volatile memory the CPU relates with directly — it temporarily stores data, programs, or program results. Because it's volatile, everything in RAM is lost on power failure or shutdown.

FeatureDynamic RAM (DRAM)Static RAM (SRAM)
RefreshingRequires continuous refreshing to retain dataDoes not require refreshing
SpeedSlower than SRAMFaster than DRAM
Storage capacityHolds a large amount of data (cell = 1 transistor + 1 capacitor, so cells are tiny)Lower capacity — each cell needs more circuitry (flip-flops)
CostLess expensiveExpensive
Power consumptionLowerHigher
Real-life analogyA whiteboard that fades and must be re-traced every few seconds to stay legibleA whiteboard that stays legible on its own, but is more expensive to install
🗣️ Plain English

DRAM cells are so tiny (just a transistor + capacitor) that millions fit on one chip — so DRAM chips hold more data per chip than SRAM, but the capacitor "leaks" charge and needs constant refreshing, which slows it down.

1.3 Primary Memory — ROM

ROM (Read Only Memory) stores permanent information — it can only be read, not written to or modified (with some exceptions below). It holds firmware: software that resides in ROM to control the processor and generate signals, including the crucial boot instructions needed to start the computer. Because it's non-volatile, this data survives power loss.

▼ The five types of ROM — click to expand
  • Masked ROM (MROM) — programmed by the manufacturer at production time; the user can never alter it. Ideal for fixed firmware.
  • PROM — blank when manufactured; the user can write to it once using a PROM programmer/burner. After that, it can't be changed.
  • EPROM — can be erased and reprogrammed, but only by exposing the chip to strong ultra-violet (UV) light after removing it from the circuit.
  • EEPROM — erasable using a high-voltage electrical charge, no UV light or chip removal needed.
  • Flash ROM — written to in small chunks called sectors/blocks; content survives power loss. This is the technology behind USB flash drives and SSDs.
✅ Exam Tip

The key distinction examiners love: EPROM needs UV light exposure to erase; EEPROM erases electrically, with no need to remove the chip. That single line answers most "differentiate EPROM and EEPROM" questions.

1.4 Secondary Memory, Registers & Cache

Secondary memory (hard drives, flash drives) stores large amounts of data permanently and for extended periods.

Registers are tiny, extremely fast memory locations inside the CPU itself, typically 16–64 bits in capacity. They have the smallest storage capacity of any memory type, but the fastest access time.

Cache memory is a compact, fast memory unit located close to the CPU. It holds frequently and recently used data/instructions to reduce the time the CPU spends retrieving them from main memory.

Cache levelSpeedCapacityNotes
L1FastestSmallestClosest to the CPU core
L2Slower than L1Larger than L1Faster than L3
L3Slowest of the threeLargestShared among multiple processor cores
💡 Real-Life Example

Think of L1/L2/L3 like your desk, your filing cabinet, and the office storage room: your desk (L1) holds the few papers you're using right now and is instant to reach; the storage room (L3) holds far more, but takes longer to walk to — and is shared by the whole office.

1.5 Memory Hierarchy

Memory hierarchy is an organised arrangement of memory types by speed, cost, and size, balancing the trade-off between how fast memory is, how much it holds, and how much it costs.

The general order — from smallest/fastest/most expensive to largest/slowest/cheapest — is: Registers → Cache → Main Memory (RAM) → Secondary Storage.

TOPIC 2

Word & Byte Addressable Memory

How the CPU locates data in memory, and the calculations examiners always ask for.

2.1 Memory Addresses

A memory address is a binary number placed on the address bus by the CPU, letting it locate and access specific data during a read or write operation.

TypeHow it works
Byte addressableEach memory address corresponds to exactly one byte. To read a byte, the CPU calls its exact address directly.
Word addressableEach address corresponds to an entire word. To access a single byte inside a word, the CPU must fetch the whole word, locate the word's address, then extract the specific byte.
💡 Real-Life Example

x86, ARM, and RISC-V are all built around byte-addressable memory in modern systems.

✅ Exam Tip

RISC vs CISC, in one line: RISC is simpler and faster; CISC is more complex (larger, richer instruction set).

2.2 The Two Formulas You Need

⚠️ Formal Definitions

Total memory size = number of addresses × size of each unit (byte, or word converted to bytes).
Address bits needed = log₂(number of memory locations).

▼ Worked Examples from the notes — click to expand

Example 1 — Word addressable: A memory has 2¹⁰ addresses, word addressable, word size = 32 bits. Find total memory size.
Word size = 32 bits = 4 bytes.
Total = 1024 × 4 = 4096 bytes = 4 KB.

Example 2 — Byte addressable: A memory has 2¹⁰ addresses, byte addressable. Find total memory size.
Total = 1024 × 1 = 1024 bytes = 1 KB.

Example 3 — Address bits from size: How many address bits are needed to access 4096 bytes of byte-addressable memory?
log₂(4096) = log₂(2¹²) = 12 address bits.

Example 4 — Word addressable, reverse direction: A computer has 32 KB memory, word addressable, word = 32 bits. How many address bits are required?
32 bits = 4 bytes. Memory = 32 × 1024 = 32,768 bytes.
Words = 32,768 ÷ 4 = 8,192 = 2¹³ → 13 address bits.

TOPIC 3

Cache Memory Mapping

How the CPU decides where in the cache a block of main memory belongs — direct, fully associative, and set associative mapping.

3.1 Why mapping matters

Cache mapping determines how data from main memory is placed into cache. Efficient mapping improves performance by reducing the time needed to access frequently used data. There are three primary techniques: Direct Mapping, Full Associative Mapping, and Set Associative Mapping.

3.2 Direct Mapping

Each block of main memory maps to exactly one cache line, found using a simple modulo operation. The memory address is split into three parts: Tag (verifies the correct data is in that line), Index (finds the specific cache line), and Offset (finds the exact data inside the block).

🗣️ Plain English

Imagine a cache with 8 lockers. Every memory block is assigned a locker using "block number mod 8" — so blocks 0 and 8 must always share locker 0. Simple, but two popular blocks fighting over one locker causes a cache miss.

Live Animation

▼ Bit-count worked example (16-bit system, 256 lines, 16-byte blocks) — click to expand

Tag = 4 bits, Set/Index = 8 bits, Offset = 4 bits.

Second example — 32-bit system, direct-mapped cache, 1024 lines, 32-byte blocks. Which cache line does address 0x0001A3F4 map to?

Offset bits = log₂(32) = 5 bits.
Index bits = log₂(1024) = 10 bits.
Cache line = (Address ÷ 32) mod 1024 = (0x0001A3F4 >> 5) mod 1024 = 287 (binary 0100011111, hex 0x11F).

AdvantagesDisadvantages
Direct MappingEasy to implement; low hardware costHigh chance of cache misses if multiple blocks map to the same line; limited flexibility

3.3 Full Associative Mapping

Any block from main memory can be placed into any line in the cache. The address is split into just two parts: Tag and Offset. The tag is compared against every tag stored in the cache to find a match.

🗣️ Plain English

Instead of an assigned locker, any block can go into any free locker — but now, finding it means checking every single locker's label. More freedom, more searching.

▼ Worked example (128 words, 8 words/line) — click to expand

Offset = log₂(8) = 3 bits.
Bit address = log₂(128) = 7 bits.
Tag = 7 − 3 = 4 bits.

AdvantagesDisadvantages
Full AssociativeFewer conflict misses; better cache utilization with varying access patternsComplex implementation (parallel tag search); higher power use; costlier hardware

3.4 Set Associative Mapping

A compromise between the two: the cache is divided into sets, each containing multiple lines. A block maps to a specific set (via the set index), but can occupy any line within that set. The address splits into Tag, Set Index, and Offset.

AdvantagesDisadvantages
Set AssociativeGood balance of complexity vs flexibility; fewer conflict misses than direct mapping; better utilization than direct mappingComplexity and power usage rise as associativity increases
✅ Exam Tip

Direct = one possible line (fast, rigid). Full Associative = any line, all tags searched (flexible, expensive). Set Associative = any line within one set — the middle ground examiners always ask you to justify.

3.5 Compare all three

FeatureDirectFull AssociativeSet Associative
Placement freedomExactly 1 lineAny lineAny line within 1 set
Address partsTag, Index, OffsetTag, OffsetTag, Set Index, Offset
Conflict missesHighLowestReduced vs Direct
Hardware costLowestHighestModerate
Real-life analogyAn assigned locker per itemAny free locker, search all labelsAn assigned row of lockers, pick any locker in that row
TOPIC 4

Virtual Memory & Control Unit

How a computer pretends to have more RAM than it does, and how the CPU generates the signals that drive it.

4.1 Virtual Memory

Virtual memory is a memory management technique that gives applications the illusion of a large, contiguous block of memory, even when physical RAM is limited and fragmented. It separates the virtual address from the physical address, using both RAM and disk to load only the parts of a program needed at a given moment.

🗣️ Plain English

It's like a hotel that "oversells" rooms because it knows not everyone checks in at once — the disk quietly holds the overflow (as swap space) and shuffles it into RAM only when a guest (a page) actually needs to be "in the room."

Key concepts

  • Paging — virtual memory is divided into fixed-size pages; physical memory into matching frames. When RAM runs out, unused pages move to disk, into an area called swap space.
  • Page Tables — OS-maintained data structures tracking which virtual page maps to which physical frame.
Detail
AdvantagesSupports multiprogramming and larger programs via demand paging; enhances security by isolating each process's address space
ThrashingIf RAM is exhausted, the system spends more time swapping pages than executing instructions — slower performance
Page faultOccurs when a program accesses a virtual page currently on disk — the OS pauses the process, fetches the page into a free frame, and updates the frame table

4.2 Control Unit

The Control Unit is the CPU component that directs the processor's operation by generating control signals. There are two major types.

FeatureHardwired Control UnitMicroprogrammed Control Unit
How signals are madeFixed logic circuits — logic gates, decoders, flip-flopsA stored sequence of micro-instructions in a special control memory (control store)
SpeedFasterSlower
Typical useRISC architectures—
Modifying the instruction setRequires physically rewiring the circuit — hardEasy to design and modify
Complexity as instruction set growsBecomes complex and hard to manageStays flexible
💡 Real-Life Example

Hardwired control is like a machine built from fixed gears — powerful and fast, but re-tooling it means physically rebuilding it. Microprogrammed control is like a machine driven by a punch-card program — slower per instruction, but you just swap the punch cards to change behaviour.

Key microprogramming terms: a control word is a word whose individual bits each represent a control signal for one step; a micro-routine is the sequence of control words for one full instruction; each individual control word is a micro-instruction; and the control store is the special memory holding all micro-instructions for the full instruction set.

TOPIC 5

Buses & I/O Data Transfer

How data actually moves between the CPU, memory, and peripheral devices — and the three competing strategies for I/O.

5.1 Buses

Data transfer is the movement of data between components — registers, memory, I/O devices, and the CPU — made possible through buses: sets of communication lines used to transfer information.

BusPurposeDirection
Data BusTransfers the actual data. Its width defines how much data moves at once.Bi-directional
Address BusCarries memory addresses.Usually unidirectional, from the CPU
Control BusCarries control signals — read, write, interrupt, acknowledge, clock.—

5.2 Three ways to move I/O data

Data transfer to and from peripheral devices can happen via Programmed I/O, Interrupt-Initiated I/O, or Direct Memory Access (DMA).

Live Animation

Programmed I/O vs Interrupt I/O vs DMA

Programmed I/O: the CPU itself repeatedly polls the device's status register, wasting cycles until data is ready.
TechniqueHow it worksAdvantageDisadvantage
Programmed I/OCPU initiates the transfer and continuously polls the device status register until ready, then moves data via its own registerEasy to implement, minimal hardware, cost effectiveBusy-waiting wastes CPU cycles; CPU can't do other work while polling
Interrupt I/OCPU executes other tasks and is only interrupted by a signal from the device when it's readyFrees CPU time, faster responseMore complex hardware and software
DMAA DMA Controller (DMAC) takes control of the buses and transfers data directly between device and RAM, bypassing the CPU; alerts the CPU via interrupt when doneCPU almost entirely freed from the transferRequires dedicated DMAC hardware

5.3 The three DMA modes

ModeBehaviour
Burst ModeDMAC takes full control of the system bus and transfers the entire data block at once. The CPU stops working until it's done.
Cycle Stealing ModeDMAC transfers a single byte/word, then releases the bus back to the CPU — repeatedly requesting one clock cycle at a time.
Transparent ModeDMAC only uses the bus when the CPU is idle, so the CPU is never interrupted.
🗣️ Plain English

Burst = "excuse me, I need the whole desk for 10 minutes." Cycle stealing = "can I just grab the desk for one second, again and again?" Transparent = "I'll only use the desk when you've stepped away."

TOPIC 6

Fault Tolerance

Designing systems that keep working even when a component fails.

6.1 What is fault tolerance?

Fault tolerance is the design and implementation technique that lets a system continue operating even when one or more of its components fail. It splits into Hardware and Software fault tolerance.

6.2 Hardware Fault Tolerance

  • Triple Modular Redundancy (TMR) — three redundant copies of a module run the same task simultaneously; a vote is taken and the majority result wins. Can track only one fault at a time.
  • Information Redundancy — e.g. parity bits: extra bits are added to detect and correct errors.

6.3 Software Fault Tolerance

  • N-Version Programming — multiple teams independently write separate versions of a program from the same requirements, using different algorithms/logic. All N versions run simultaneously, and a centralized decision algorithm picks the best output by majority vote.
  • Exception Handling — the system detects an abnormal event and redirects execution flow to prevent the error from propagating.
💡 Real-Life Example

Applications include aviation systems (aircraft control must survive component failure), medical systems (life support, patient monitoring), space exploration (spacecraft/satellites), and industrial automation (continuous plant monitoring).

TOPIC 7

Parallelism & Flynn's Taxonomy

Doing more than one thing at once — the types of parallelism, and how Flynn classified processor architectures around it.

7.1 Parallelism vs Concurrency

Parallelism is a computer system's ability to perform multiple operations simultaneously, improving computational speed and system performance. Modern applications — AI, image processing, big data analytics — demand enormous computational power that parallelism helps meet.

🗣️ Plain English

Concurrency is one cashier rapidly switching between two customers. Parallelism is two cashiers serving two customers at the exact same time.

7.2 Four types of parallelism

TypeHow it's achieved
Bit-LevelIncreasing the processor's word size, so more bits are processed at once
Task-LevelDecomposing a task into sub-tasks and executing them simultaneously
Data-LevelApplying the same operation to multiple data elements at once (e.g. graphics/vector processing)
Instruction-LevelExecuting multiple instructions simultaneously within one processor

Instruction-level parallelism is achieved via Instruction Pipelining (overlapping execution of independent instructions) and Superscalar Architecture (executing multiple instructions per clock cycle using multiple ALUs).

7.3 Flynn's Taxonomy

Introduced by Michael J. Flynn in 1966, this classifies computer architectures by how they handle instruction and data streams — four categories.

Live Animation

Flynn's Taxonomy — Instruction & Data Streams

SISD: a uniprocessor executes one instruction on one data stream at a time, sequentially.
ModelMeaningBest suited for
SISDSingle Instruction, Single Data — a uniprocessor, sequential processingGeneral-purpose sequential computing
SIMDSingle Instruction, Multiple Data — same instruction runs on all CPUs, each on different dataMatrix operations, image processing, scientific computing
MISDMultiple Instruction, Single Data — different instructions on different processing elements, all sharing one data setRare — few machines built, none commercially available
MIMDMultiple Instruction, Multiple Data — each processing element has its own instruction and data streamAny kind of application

7.4 MIMD: Shared vs Distributed Memory

FeatureShared MemoryDistributed Memory
Memory accessAll processors read/write the same physical memoryEach computer has its own memory, connected via a high-speed network — no global address space
Getting remote dataDirect accessMust explicitly communicate — called message passing
AdvantageLow communication latency, simpler programming modelHighly scalable
DisadvantagePoor scalabilityDesynchronization risk

A Hybrid Model combines both: large clusters group processors into smaller shared-memory units, then network those units in a distributed-memory structure.

💡 Real-Life Example

Multi-core processing puts multiple cores on a single chip — dual-, quad-, hexa-, octa-, and deca-core designs — increasing performance and multitasking while reducing power consumption per operation.

TOPIC 8

Harvard vs Von Neumann Architecture

Why separating instruction and data memory removes a fundamental bottleneck.

8.1 Harvard Architecture

Harvard Architecture overcomes the bottleneck of Von Neumann architecture by using separate memory for program instructions and data, and separate buses for each. This lets the processor fetch an instruction and a piece of data simultaneously. It originates from Harvard University's architecture work in the 1940s.

Components: CPU, Program/Instruction Memory, Data Memory, Instruction Bus.

Live Animation

Fetch Race: Harvard vs Von Neumann

Harvard has two buses, so instruction and data fetch happen in the same cycle. Von Neumann shares one bus, so they queue one after another.
FeatureHarvard ArchitectureVon Neumann
MemorySeparate instruction & data memoryShared memory
BusSeparateSingle bus
Memory accessSimultaneousSequential
SpeedFasterSlower
ComplexityMore complexSimpler
▼ Advantages, disadvantages & real devices — click to expand

Advantages: faster execution (simultaneous fetch), eliminates the Von Neumann bottleneck, efficient pipelining, increased bandwidth (two buses), and data security (program memory protected from accidental modification).

Disadvantages: more costly and complex; harder to write self-modifying code since instruction and data memory are accessed separately.

Used in: microcontrollers, digital signal processors, embedded systems, robotics, automotive control systems, medical equipment. Real devices: SIM32 microcontrollers, Atmel AVR, Microchip PIC.

TOPIC 9

Systolic Arrays

Grids of processors that pass data and computation between neighbours in rhythmic waves — named after the rhythmic flow of blood through the heart.

9.1 What is a systolic array?

A systolic array is a configuration of processors that rhythmically perform computation and transfer data through the network. Each processor performs a small computation and passes the result to its neighbours until a final output is obtained.

🗣️ Plain English

Picture a bucket brigade at a fire — each person doesn't run to the fire and back; they just pass the bucket to their neighbour, do a tiny bit of work, and pass it on. The whole line moves in rhythm.

Live Animation

Data Pulsing Through a 2D Systolic Array

Each pulse, every processing element (PE) does a small computation using data from its neighbours, then passes its result onward — matrix multiplication is the classic example.

9.2 Components

  • Processing Elements (PEs) — the basic computational units; each has an ALU, registers, control logic, and local memory
  • Input Channel — feeds data into the first row/column of PEs
  • Output Channel — collects processed results from the final row/column
  • Communication Links — transfer data between neighbouring PEs
  • Clock — synchronizes all operations across the array

9.3 Types & applications

TypeLayoutApplications
LinearPEs arranged in a lineSignal filtering
Two-Dimensional (most common)PEs in rows/columnsMatrix multiplication, neural networks, image processing
Multi-DimensionalA grid pumping data through multiple directions, maximizing local data reuseDigital signal processors, deep learning accelerators, Google's Tensor Processing Units (TPUs)

General applications also include digital signal processing (FFT), image/video processing, cryptography (encryption, hashing), and scientific computing (weather forecasting, engineering analysis).

AdvantagesDisadvantages
Systolic ArraysHigh parallelism; regular, modular design; robust, compact, efficientHighly specialized and inflexible; expensive

Key Terms & Glossary

Quick reference — the definitions examiners phrase as "define X."

DRAM
RAM that needs continuous refreshing to retain data; slower but cheaper and denser than SRAM.
SRAM
RAM that holds data without refreshing as long as it has power; faster but more expensive than DRAM.
Firmware
Software residing in ROM that controls the processor and generates signals.
Memory Hierarchy
The organised arrangement of memory types by speed, cost, and size, from registers down to secondary storage.
Byte Addressable
Each memory address corresponds to exactly one byte.
Word Addressable
Each memory address corresponds to a full word; individual bytes must be extracted after fetching the word.
Cache Mapping
The method by which a main-memory block is assigned a location in cache — direct, full associative, or set associative.
Tag / Index / Offset
The three parts a memory address splits into for cache lookup: tag verifies the data, index/set locates the line, offset locates the byte within the block.
Virtual Memory
A technique giving programs the illusion of large, contiguous memory by combining RAM and disk via paging.
Thrashing
Excessive page swapping between RAM and disk that slows the system more than it would if RAM were sufficient.
Page Fault
An event where a program accesses a virtual page that is currently stored on disk, not in RAM.
Control Unit
The CPU component that generates control signals directing the processor's operation — hardwired or microprogrammed.
Bus
A set of communication lines used to transfer information — data, address, or control.
DMA
Direct Memory Access — lets I/O devices transfer data to/from memory directly, bypassing the CPU, via a DMA Controller.
Fault Tolerance
Design techniques that let a system keep working despite one or more component failures.
Flynn's Taxonomy
A 1966 classification of computer architectures by instruction/data stream count: SISD, SIMD, MISD, MIMD.
Message Passing
The explicit communication method processors in a distributed-memory system use to exchange data.
Systolic Array
A grid of processing elements that rhythmically compute and pass data to neighbours until a final result emerges.

Likely Exam Questions

Predicted from the structure of the notes — every worked example and every "difference between X and Y" is a strong signal for CSC 422.

LIKELY QUESTION

Differentiate between DRAM and SRAM, and explain why DRAM chips can hold more data than SRAM chips of the same size.

📍 See Topic 1.2
DRAM stores each bit using a transistor + capacitor pair, which is very small, so millions fit on one chip — but the capacitor's charge leaks, requiring continuous refreshing, which makes DRAM slower. SRAM uses flip-flop circuitry per bit, which needs more transistors per cell (so lower density) but retains data without refreshing, making it faster and more expensive with higher power draw.
LIKELY QUESTION

A memory system has 2¹² addresses and is word addressable with a word size of 16 bits. Calculate the total memory size in bytes and KB.

📍 See Topic 2.2 — try it in the calculator above
16 bits = 2 bytes per word. Total = 4096 × 2 = 8192 bytes = 8 KB. (Follows the same method as Example 1 in the notes: addresses × bytes-per-word.)
LIKELY QUESTION

Explain direct mapping, full associative mapping, and set associative mapping, and state one advantage and one disadvantage of each.

📍 See Topic 3.2 – 3.5
Direct mapping assigns each memory block to exactly one cache line via a modulo operation — easy and cheap, but prone to conflict misses. Full associative mapping allows any block into any line, checking all tags in parallel — flexible with fewer conflict misses, but hardware-expensive and complex. Set associative mapping divides the cache into sets, each block maps to one set but can occupy any line within it — a balance between the two, with moderate complexity and reduced conflict misses versus direct mapping.
LIKELY QUESTION

A direct-mapped cache has 512 lines and a block size of 16 bytes in a 32-bit address system. How many bits are used for the offset and the index?

📍 See Topic 3.2
Offset bits = log₂(16) = 4 bits. Index bits = log₂(512) = 9 bits. Tag bits = 32 − 9 − 4 = 19 bits. (Same method as the 0x0001A3F4 worked example in the notes.)
LIKELY QUESTION

What is virtual memory? Explain thrashing and page faults, and how virtual memory improves security.

📍 See Topic 4.1
Virtual memory gives applications the illusion of a large, contiguous memory space by combining RAM with disk storage using demand paging, separating virtual addresses from physical ones. Thrashing occurs when RAM is exhausted and the system spends more time swapping pages than executing instructions, degrading performance. A page fault occurs when a program accesses a virtual page currently on disk — the OS pauses the process, fetches the page into a free frame, and updates the frame table. Security is improved because each process operates in its own isolated virtual address space, unable to directly access another process's memory.
LIKELY QUESTION

Differentiate between Programmed I/O, Interrupt I/O, and DMA. Which is most CPU-efficient and why?

📍 See Topic 5.2 — watch the animation above
Programmed I/O has the CPU busy-wait, continuously polling the device status register — simplest hardware but wastes CPU cycles. Interrupt I/O lets the CPU do other work and only responds when the device signals via interrupt — more efficient but needs more complex hardware/software. DMA is the most CPU-efficient: a DMA Controller transfers data directly between the device and memory, bypassing the CPU almost entirely, and only interrupts the CPU once the transfer is complete.
LIKELY QUESTION

Describe the three DMA transfer modes.

📍 See Topic 5.3
Burst Mode: the DMAC takes full control of the bus and transfers an entire data block at once, pausing the CPU until it's done. Cycle Stealing Mode: the DMAC transfers a single byte or word at a time, releasing the bus back to the CPU between transfers. Transparent Mode: the DMAC only uses the bus during CPU idle cycles, so the CPU is never interrupted by the transfer.
LIKELY QUESTION

Using Flynn's Taxonomy, classify computer architectures and give one real-world use case for each classification.

📍 See Topic 7.3 — try the animation tabs above
SISD: a single uniprocessor executing one instruction on one data stream sequentially — general-purpose computing. SIMD: the same instruction runs across multiple processors on different data streams simultaneously — used in image processing and scientific/matrix computing. MISD: different instructions operate on the same data set across processors — rare, with no significant commercial machines. MIMD: each processing element runs its own instructions on its own data — used in modern multi-core and distributed systems, capable of any application.
LIKELY QUESTION

Explain how Harvard Architecture eliminates the Von Neumann bottleneck.

📍 See Topic 8.1 — watch the fetch race animation above
In Von Neumann architecture, instructions and data share one memory and one bus, so the CPU must fetch them sequentially, one at a time — this queuing is the "bottleneck." Harvard Architecture uses separate memories and separate buses for instructions and data, allowing the processor to fetch an instruction and a piece of data in the same clock cycle. This removes the wait entirely, improving execution speed and enabling more efficient pipelining, at the cost of higher hardware complexity and expense.
LIKELY QUESTION

What is a systolic array? Describe its components and give two real-world applications.

📍 See Topic 9.1 – 9.2
A systolic array is a grid of processing elements (PEs) that rhythmically compute on data and pass results to neighbouring PEs until a final output emerges — named for the rhythmic flow of blood through the heart. Its components are the PEs (each with an ALU, registers, control logic, local memory), input/output channels, communication links between neighbours, and a synchronizing clock. Real-world applications include matrix multiplication, neural network acceleration (e.g. Google's Tensor Processing Units), and digital signal processing such as the Fast Fourier Transform.
